# Гид сценариста

Как писать заказ в `.rom`. Обязателен к прочтению перед работой: `docs/rom-language.md` (синтаксис), `docs/world.md` (тон, регистры), `docs/characters.md` (голоса), `docs/locations.md` (идентификаторы локаций), `docs/orders.md` (бриф заказа). Эталон: `content/orders/velt_01.rom`.

## Файл заказа

Один заказ — один файл `content/orders/<id>.rom`. В файле:

1. Флаги заказа: `flag <id>_… "описание"`. Все флаги с префиксом идентификатора заказа (`velt07_pol_broken`). Общие флаги из `content/registry.rom` и `content/keys.rom` можно использовать, но не объявлять заново.
2. Декларация `order` с `requires`, `start`, `finish`, `done`, `brief` по строке из `docs/orders.md`. `requires` обычно `done(<предыдущий>) >= 1`, плюс память или репутация, если указано.
3. Сцены. Ключевые сцены заказа: `[key] loc=<локация> order=<id>` с `when`. Они срабатывают при входе в локацию или при `@hub`/`@next`. Последующие сцены без `loc`, достигаются по ссылке.
4. Сцена развязки (`finish`): ставит репутацию, даёт фрагмент памяти `memory own run_{runs}_<id> "…"`, ведёт `-> @unload`. После развязки только `@unload`.

Нельзя редактировать `registry.rom`, `keys.rom`, `meta.rom`, файлы локаций и файлы чужих заказов. Новый персонаж: `character <id>_<кто> "Имя"` в своём файле. Идентификаторы фрагментов памяти с префиксом заказа.

## Структура заказа

- 8–20 сцен, 900–2000 слов.
- Стартовая локация задана брифом. Ключи заказа разбросаны по 3–5 локациям, чтобы игрок двигался. Хотя бы одна ключевая сцена в локации, куда идти не обязательно: награда за любопытство.
- `done` ставится флагом в конкретном месте (сдать, отправить, вернуться), а не сразу после получения предмета. Между получением и сдачей должно быть искушение.
- Минимум два тупика, и не меньше 20% выборов ведут в тупик. Линт предупредит. Квота не применяется к заказам-развязкам и «откровениям» без тупиков по брифу (`velt_12`, `marsh_04`, `hanna_03`, `silence_01`, `mori_03`, `mori_04`, `sato_04`, `koenig_03`, `koenig_04`, `zero_04`). Типы: `dead:unload` (носитель рассыпался, `-> @unload`), `dead:intercept` (Тьюринг, `-> @unload`), `dead:silent` (без объяснения, `-> @unload`), `dead:loss` (необратимая потеря: предмет, память, союзник; заказ может остаться выполнимым, забег продолжается), `dead:refusal` (заказ провален: движок сам закрывает забег — до трёх переходов домой, затем сцена `fail`). У сцены `loss` выборы ведут в `@hub`.
- Если в заказе есть `dead:refusal`, объявите поле `fail <scene>` и напишите сцену провала. Без поля сработает общий `config fail`, но у заказа с отказами должна быть своя. Требования к сцене `fail`: 5–9 абзацев, один экран, база заказчика или дорога домой (движок возвращает деку к `start` заказа, так что не называй локацию, где игрок провалился), `rep <client> -1`, фрагмент `memory own fail_{runs}_<id>`, ровно один выбор `-> @unload`.
- Тупик должен выглядеть разумным выбором. Плохой тупик: «прыгнуть в пропасть». Хороший: «заплатить за проход» там, где платить значит признать долг.
- Фрагменты памяти: 2–10 за заказ, из них 2–4 на конкретное прохождение — у разных исходов свои фрагменты. Виды: `own` (что сделала Рен), `hanna` (жизнь до льда, редко), `foreign` (чужое, только через Тишину, осколки, Ржу, Кёниг).
- Один абзац `~dossier`, `~echo` или `~intrusion` на заказ, не больше двух. Это приправа.
- Хотя бы одна сцена с ровно одним выбором. Хотя бы одна сцена, где выбор с `[memory n]` заштрихован для новичка и открывает короткий путь ветерану.

## Голос

- Гибсон, не Кусанаги. Никто не говорит «философия», «сознание», «личность» в лоб. Всё через сделки, цены, отказы.
- Реплики: `Имя: — текст`. Имя из `content/registry.rom` или объявленное в файле. Реплики Рен: `Рен: — …`. В кнопках имя не пишется.
- Абзацы короткие. Технология через износ и цену. Ни одного восклицательного знака от повествователя.
- Регистр: описания в сценах развёрнутые, но сухой абзац после трёх развёрнутых это удар. Используйте его для боли, потери, выгрузки.
- Тишина: строчные, без «я» до библиотеки. Ржа: строчные с заглавными посреди слов, повторы, «я» и «ты» путаются.
- Марш не глупая. Раск глупее, но не карикатура. Вельт никогда не говорит с Рен напрямую. Сато вежлив всегда. Кёниг говорит «лот». Поль спрашивает, больно ли. Пеу не спрашивает ничего.

## Повторяемость

- Сцена, которая не может случиться дважды за игру (смерть, единственный предмет, первая встреча): `[once]` для сцен пула, или `when seen(<id>) == 0` для ключей.
- Ключи заказа срабатывают один раз за забег автоматически. Если заказ проваливается и игрок берёт его снова, сцены повторятся: пишите так, чтобы второй раз читался как второй (`? if seen(<id>) > 0`, хотя бы одна строка).
- Персонажи не помнят Рен между забегами, кроме Марш (по досье), Виейры (по деньгам) и Кёниг (по учёту). Рен помнит всех. Игра на этой асимметрии.

## Старый текст

Тексты предыдущей версии лежат в истории: `git show HEAD~0:src/content/act1.ts` (и `act2.ts`, `act3.ts`) или `git log --all -- src/content`. Их можно и нужно резать на сцены новых заказов, если бриф на них указывает: бюро Тьюринга (K5), храм (K7), Морияма узнаёт (K9), Дзион (K10), звонок Ханны, рейд в Оно-Сэндай, вербовщики, дилер. Переносить дословно можно, переписывать под новый контекст нужно.

## Проверка

```
npm run lint
npm run stats
```

Ноль ошибок в своих файлах. Ошибки в чужих файлах во время параллельной работы игнорировать и перезапускать. Доля тупиков по своему заказу в `npm run stats` не ниже 20%.
