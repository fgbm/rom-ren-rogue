# Язык сценариев `.rom`

Весь контент игры лежит в `content/**/*.rom`. Файлы компилируются в один JSON при сборке (Vite-плагин) и проверяются линтом (`npm run lint`). Движок исполняет JSON и не содержит ни строчки сюжета.

Цель языка: описывать сцены как данные, чтобы весь сценарий был однонаправленным графом, который можно проверить автоматически: достижимость, тупики, циклы, опечатки в флагах и предметах, пороги памяти, имена говорящих.

## Общие правила

- Кодировка UTF-8. Разбор построчный. Блоки задаются отступом в два пробела.
- Строка, начинающаяся с `#`, комментарий.
- Пустые строки игнорируются.
- Идентификаторы: латиница, цифры, `_`, точка (`ninsei.market`, `velt_01`).
- Строковые литералы в кавычках `"…"`.
- Каждая непустая строка внутри текстового блока это один абзац.

## Декларации верхнего уровня

### Реестры

```
config intercept=turing_intercept flatline=flatline unload=unload first=velt_01
ladder 3 5 8 10 12 15 18 25 40

item ice_kuang "«Куан» 11" [consumable]
  Китайский военный ледокол. Входит в лёд тихо.

character marsh "Марш" aliases "Инспектор Марш"
flag marsh_deal "Рен договорилась с Марш в бюро"
faction marsh
```

- `config`: служебные сцены и первый заказ.
- `ladder`: допустимые пороги памяти. Любой другой порог в `[memory n]` или `memory >= n` это ошибка линта.
- `item`: предмет. Тело блока это описание. Тег `[consumable]` означает, что предмет сгорает при применении.
- `character`: говорящий. Реплика `Имя: — …` допускается только для объявленного имени или алиаса.
- `flag`: флаг забега. Неизвестный флаг это ошибка.
- `faction`: ключ репутации для `rep`.

### Заказчик

```
client velt "Вельт"
  label Вельт. Ликвидатор. Достать и вернуть на баланс.
  credit 3000
  attention 1
  items ice_old
  unlocked
```

`unlocked` означает доступен с начала игры. Остальные открываются эффектом `unlock`.

### Локация

```
location ninsei.market act=1 "Чёрный рынок"
  dry
    Подвал. Три уровня вниз. Старик, три деки.
  rich
    Чёрный рынок Ниндзэя работает в подвале под баром, который работает в подвале под лапшичной…
    ? if memory >= 8
      Ты знаешь, сколько ступеней. Ты не считала.
  exit "Наверх, в переулок." -> ninsei.alley
  exit "Дальше вниз." -> ninsei.market_deep [memory 5]
  exit "К лифту грузового." -> ninsei.docks [item dub]
      attention +1
```

- `act` определяет город и подпись в статусе: 1 Тиба, 2 Муравейник, 3 Фрисайд.
- `dry` и `rich` два регистра описания. Движок выбирает регистр по состоянию (см. `docs/world.md`, «Регистры»). Внутри обоих работают условные блоки.
- `exit`: переход. Подпись в кавычках, цель после `->`. Теги как у выбора: `[when expr]`, `[item x]`, `[memory n]`, `[cost n]`. Вложенные строки это эффекты при переходе.

### Заказ

```
order velt_01 client=velt "Реестр"
  requires runs >= 1
  start ninsei.coffin
  finish velt_01_end
  done flag(registry_taken)
  brief
    Виейра: — Вельт хочет реестр активов клана…
```

- `requires`: условие доступности на экране выбора заказа.
- `start`: локация, где Рен просыпается.
- `finish`: сцена развязки. Она становится ключевой, как только выполнено `done`, и должна вести в `@unload`.
- `brief`: абзацы, которые Виейра говорит при загрузке. Показываются в сцене загрузки.

### Сцена

```
scene ninsei.market_sell [pool once] loc=ninsei.market
  when !has(shard)
  enter
    dossier moriyama
  Старик смотрит на носитель.
  Старик: — Продай. Дам хорошо.
  ~memory [if memory >= 3]
    Ты помнишь, что он предлагал в прошлый раз меньше.
  * Отказаться.
      -> @hub
  * Спросить, сколько. [dead:refusal]
      rep viejra -1
      -> ninsei.market_price
```

Теги сцены:

| Тег | Смысл |
|---|---|
| `key` | Ключевая. Показывается режиссёром, когда `when` истинно, один раз за забег, приоритет над пулом. |
| `pool` | Событие локации. Режиссёр выбирает случайно при входе в локацию. Один раз за забег. |
| `once` | Один раз за всю игру. Для сцен, которые не могут повториться правдоподобно (умирающий сосед, первая встреча). |
| `silence` | Узел Тишины: интерфейс приглушён, абзацы без имени. |
| `rust` | Узел Ржи: то же, но другой регистр. |
| `shop` | Магазин: недоступные по кредиту выборы показываются с ценой. |
| `dead:<тип>` | Тупик. Типы: `unload` (выгрузка), `intercept` (перехват), `loss` (необратимая потеря), `refusal` (заказчик отказал), `silent` (без объяснения). `unload`, `intercept`, `silent` ведут только в `@unload`. `loss` и `refusal` необратимы, но забег продолжается: заказ уже нельзя выполнить или что-то потеряно навсегда. |

Параметры: `loc=` локация, где сцена может сработать; `order=` заказ, при котором сцена активна. Сцена без `loc` доступна только по прямой ссылке. Сцена без `order` активна при любом заказе.

Поля: `when expr` условие показа режиссёром; `enter` эффекты при входе.

## Абзацы

- Обычная строка это абзац повествования.
- `Имя: — текст` реплика. Имя должно быть объявлено через `character`.
- `~вид текст` абзац особого вида в одну строку. `~вид` с вложенным блоком: каждая строка блока абзац этого вида.
- Виды: `silence` (строки Тишины), `rust` (строки Ржи), `memory` (фрагмент памяти), `item` (получен предмет), `echo` (реплика из прошлого забега), `dossier` (запись из блокнота Марш), `intrusion` (чужое воспоминание перебивает сцену).
- `~echo` и `~intrusion` без текста: движок подставит случайный фрагмент памяти нужного вида (свой для эха, чужой для вторжения). Если фрагментов нет, абзац не показывается.
- Условие абзаца: суффикс `[if expr]` в конце строки.
- Условные блоки:

```
? if memory >= 5
  Ты помнишь дыру.
? elif has(ice_kuang)
  «Куан» найдёт дыру сам.
? else
  Ты идёшь напролом.
```

- Подстановки: `{credit}`, `{memory}`, `{runs}`, `{attention}`, `{integrity}`, `{client}`, `{order}`.

## Выборы

```
* Текст кнопки. [cost 2000] [memory 8] [item ice_kuang] [when expr] [dead] [back] -> цель
    эффект
    эффект
    -> цель
```

- Ровно одна цель: либо в конце строки, либо строкой `-> цель` в блоке.
- `[cost n]`: кредит. Вне магазина выбор скрыт, если денег нет; в магазине показан, но заблокирован.
- `[memory n]`: показан, заштрихован по дефициту, заблокирован, пока памяти меньше `n`.
- `[item x]`: показан только с предметом. Расходник сгорает.
- `[when expr]`: скрыт, если ложь.
- `[dead]`: пометка, что выбор ведёт в тупик. Линт требует, чтобы цель была сценой с тегом `dead:*`.
- `[back]`: разрешённое обратное ребро (например, «вернуться к прилавку»). Единственный способ создать цикл.

Цели:

| Цель | Смысл |
|---|---|
| `id` | Сцена. |
| `@hub` | Вернуться в описание текущей локации с выходами. |
| `@next` | Отдать решение режиссёру (ключ, событие пула, иначе хаб). |
| `@go loc` | Переместиться в локацию `loc` и отдать решение режиссёру. |
| `@unload` | Выгрузка, конец забега. |

## Эффекты

```
give ice_kuang
take manifest
flag +marsh_deal
flag -fleeing
rep marsh +2
attention +1
integrity -1
credit -1000
memory own coffin_no "Умирающий ковбой спросил, сохранять ли слепок. Ты сказала: нет."
unlock marsh
dossier marsh
move freeside.docks
ending 2
wipe
chance 0.5: integrity -1; flag +tunnel_hit
```

Несколько эффектов на одной строке разделяются `;`. `chance p:` выполняет эффекты после двоеточия с вероятностью `p`. `move` меняет локацию без показа хаба. `ending n` записывает концовку. `wipe` стирает мету.

## Выражения

Атомы: числа, строки, `memory`, `memory.own`, `memory.hanna`, `memory.foreign`, `credit`, `attention`, `integrity`, `runs`, `client`, `act`, `loc`, `order`.

Функции: `has(item)`, `flag(name)`, `rep(faction)`, `seen(scene)` (сколько раз за всю игру), `visited(scene_or_loc)` (в этом забеге), `done(order)` (сколько раз выполнен), `memory(id)` (есть ли фрагмент), `ending(n)`.

Операторы: `== != < <= > >=`, `&& || !`, скобки. Голый идентификатор справа от `==` сравнивается как строка: `client == marsh`.

## Режиссёр

При входе в локацию и при `@next`:

1. Целостность 0 → `flatline`. Внимание 5 → `intercept`, один раз за забег.
2. Ключевая сцена: `key`, `loc` совпадает (или отсутствует), `order` совпадает (или отсутствует), `when` истинно, не показана в этом забеге, для `once` не показана никогда. Первая по порядку файлов.
3. Сцена развязки текущего заказа, если `done` истинно.
4. При входе в локацию (не при `@hub`): событие пула этой локации, не показанное в этом забеге, для `once` никогда, показанное меньше шести раз за всё время. Случайное.
5. Хаб: описание локации в нужном регистре и выходы.

## Линт

Ошибки (сборка падает):

- Дубликат идентификатора; ссылка на несуществующую сцену, локацию, предмет, флаг, заказчика, фракцию, заказ.
- Реплика с неизвестным именем говорящего.
- Сцена недостижима: не имеет `loc` с `key`/`pool`, не является `finish` заказа, не служебная и никто на неё не ссылается.
- Цикл в графе сцен, не проходящий через `[back]`, `@hub`, `@next`, `@go`.
- Сцена без выборов без тега `dead:*`.
- Выбор `[dead]` ведёт не в `dead:*`-сцену.
- Сцена `finish` заказа не ведёт в `@unload`.
- Порог памяти вне `ladder`.
- Локация без обоих регистров описания или без выходов (кроме помеченных `[terminal]`).
- Локация, недостижимая из стартовых локаций заказов по выходам и `@go`/`move`.

Предупреждения:

- Флаг проверяется, но нигде не ставится.
- Предмет объявлен, но никогда не выдаётся.
- В заказе меньше 20% выборов ведут в тупик.
- Сцена пула без `once` в локации, где сюжет предполагает однократность (проверяется по списку в `docs/orders.md`).

Команды:

```
npm run lint          # проверить всё
npm run graph         # выгрузить content/graph.dot для Graphviz
npm run simulate      # случайный проходчик, статистика забегов
```

## Дополнения

- `config` также требует `load=`: сцена загрузки, в которой абзац `~brief` заменяется брифом текущего заказа.
- Цель `@orders` открывает экран выбора заказа (только из сцены выгрузки).
- Выход из локации может вести в сцену: `exit "К прилавку." -> scene:ninsei.market_shop`. Это действие в локации: магазин, рейд, разговор. Такая сцена считается достижимой. Из неё возвращаются `-> @hub`.
- В идентификаторе фрагмента памяти допустима подстановка `{runs}`: `memory own flatline_{runs} "…"`, чтобы фрагмент выдавался в каждом забеге заново.
- Эффект `forget вид n` убирает последние `n` фрагментов вида. Так забирает Ржа.
- Флаг `intercepted` ставит движок при перехвате; объявлен в реестре.
- `seen(id)` внутри самой сцены `id` считает показы до текущего: при первом показе равно нулю. Просмотр засчитывается после рендера.
- Событие пула разыгрывается один раз по прибытии в локацию, включая стартовую локацию заказа. Возврат в хаб через `@hub` событие не запускает.
- Флаги живут один забег. Условие на действие из прошлого заказа выражается через `done(order)`, репутацию или фрагмент памяти `memory(id)`, не через флаг.
